Cookie auth provides a simple method for managing authentication and user state, but is dependent on an identity provider to validate the users credentials and provide user information. ASP.net core does contain it's own implementation for this ([Asp.net core identity provider](https://learn.microsoft.com/en-us/aspnet/core/security/authentication/identity?view=aspnetcore-9.0&tabs=visual-studio)), but the most common path is to use an external OIDC identity provider.

As this workshop is focused on the ASP.net core Auth side, it will not cover specific OIDC Identity providers, or the mechanisms via which OIDC works. 

This workshop will use a dockerised version of Denude identity server, preconfigured with a number of identities.

3. Add OIDC auth config to `Program.cs` after `.AddCookie()`
	```csharp
	.AddOpenIdConnect(OpenIdConnectDefaults.AuthenticationScheme, (options) =>
	{
		// Set default sign in scheme to cookie
	    options.SignInScheme = CookieAuthenticationDefaults.AuthenticationScheme;

		// Set authentication type to descriptive value
		// Otherwise defaults to TokenValidationParameters.DefaultAuthenticationType, which is "AuthenticationTypes.Federation"
		options.TokenValidationParameters.AuthenticationType = "OIDC";

		// Address of OIDC server, can be updated in docker config
	    options.Authority = "http://localhost:4012";
	    // Name this client is registered with OIDC Server
	    options.ClientId = "WebApp";
	
	    options.ResponseType = OpenIdConnectResponseType.Code;
	    options.ResponseMode = OpenIdConnectResponseMode.FormPost;

		// Scopes to request access to
	    options.Scope.Add("email");
	    options.Scope.Add("workshop");
	    options.Scope.Add("workshop_api");
	
	    options.RequireHttpsMetadata = !builder.Environment.IsDevelopment();
	})
	```

The exceptions will be re-thrown after this event unless suppressed.                                                                                                                                                 |

## Mapping OIDC Claims

As there may be many claims involved, the OIDC scheme only maps a subset of the provided user claims into the user ClaimsIdentity. (https://learn.microsoft.com/en-us/aspnet/core/security/authentication/social/additional-claims?view=aspnetcore-9.0#map-user-data-keys-and-create-claims)

### Task Five (Extra) - Mapping claims
1. To map the "craft" claim, add the following code to the OIDC scheme configuration in `Program.cs`
	```csharp
		options.GetClaimsFromUserInfoEndpoint = true;
		options.TokenValidationParameters.NameClaimType = "given_name";
		options.ClaimActions.MapJsonKey("craft", "craft");
		options.ClaimActions.MapJsonKey("given_name", "given_name");
	```
1. Re-run WebApp and log in as an OIDC user, then go to the Task 03 view to see the additional claim.

#### Adding claims in code(Optional) 
Claims can also be added on the client during the authentication process using events. While claims identities are marked with the scheme used to authenticate them, it is sometimes needed to add or modify the received claims to line up with other sources. A Claims Transformer can also be used for this, but they are less ideal as only a single transformer can run, and it is run for all identity schemes.

	```csharp
	options.Events.OnTokenValidated = context =>
	{
		if (context.Principal is not { Identity: ClaimsIdentity claimsIdentity })
		{
			//No claims identity found after token validation
			return Task.CompletedTask;
		}
	
		claimsIdentity.AddClaims(
		[
			new Claim("AddedClaim", "ClaimValue")
		]);
	
		return Task.CompletedTask;
	};
	```
