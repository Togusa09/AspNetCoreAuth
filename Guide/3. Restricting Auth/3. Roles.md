Uses role claim to identify what roles the user has

Roles are user claims that can identify what permissions a user has. The claims to use for populating user name and roles are configurable per Claims Identity and can be passed into it's constructor. A ClaimsPrincipal can be composed of multiple Claims Identities from different sources using different claims to indicate name and role.

The role claim isn't inherently different from any other claim, and checks can be done against the users claims directly, however ASP.net provides authorization helpers , such as `User.IsInRole()`, which expect there to be a role claim specified.

## Task Four

1. Create `Task04Controller` and add the code:
	```csharp
	[Route("Task04")]
	[ApiController]
	public class Task04Controller : Controller
	{
	    [AllowAnonymous]
	    public IActionResult Index()
	    {
	        // View should already exist in workshop assets
	        return View();
	    }
	
	    [Authorize(Policy = "FlightDirector")]
	    [HttpGet("MissionControl")]
	    public IActionResult CapeCanaveralMissionControl()
	    {
	        return Json("You are in mission control");
	    }
	
	    [Authorize(Policy = "Astronaut")]
	    [HttpGet("LaunchPad")]
	    public IActionResult CapeCanaveralLaunchPad()
	    {
	        return Json("You are on the launchpad");
	    }
	}
	```
1.  Return to claims page and use role tests
	1. Test going to launchpad (Requires pilot role, so will work)
	2. Test going to mission control (Requires FlightDirector role, so will fail)
