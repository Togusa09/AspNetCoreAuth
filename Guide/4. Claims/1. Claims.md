
1. As the information for this user is hard coded in the controller, additional claims can be added by attaching them to the created identity.
	```csharp
	   identity.AddClaims(
	   [

	   ]);
	```

3. Log out, then back in as an OIDC user to view their claims
	![[ClaimsScotInitialRoles.png]]

As there may be many claims involved, the OIDC scheme only maps a subset of the provided user claims into the user ClaimsIdentity. (https://learn.microsoft.com/en-us/aspnet/core/security/authentication/social/additional-claims?view=aspnetcore-9.0#map-user-data-keys-and-create-claims)
1. Add the following code to the OIDC scheme configuration in `Program.cs`
	```csharp
		options.ClaimActions.MapJsonKey("craft", "craft");
	```
1. Re-run WebApp and log in as an OIDC user. The additional claims will now be available
	![[ClaimsScotExtraRoles.png]]

(Optional) Claims can also be added on the client during the authentication process using events. While claims identities are marked with the scheme used to authenticate them, it is sometimes needed to add or modify the received claims to line up with other sources.
```csharp
options.Events.OnTokenValidated = context =>
{
    if (context.Principal is not { Identity: ClaimsIdentity claimsIdentity })
    {
        //No claims identity found after token validation
        return Task.CompletedTask;
    }

    claimsIdentity.AddClaims(
    [
        new Claim("AddedClaim", "ClaimValue")
    ]);

    return Task.CompletedTask;
};
```

## Claims Transformation (Optional)
Implementing the `IClaimsTransformation` interface also provides a way to transform a users claims (https://learn.microsoft.com/en-us/aspnet/core/security/authentication/claims?view=aspnetcore-9.0#extend-or-add-custom-claims-using-iclaimstransformation) however it has some limitations which lead to updating claims in scheme events being preferable. Only one implementation can be registered, and it is run against all auth schemes.
