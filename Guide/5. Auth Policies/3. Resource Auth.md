Simple demo is that to access craft you need to have the claim for it

The existing Authorization configurations have been based on whether a user meets satisfies a constant requirement. Resource Authorization Handlers extend this be allowing a users authorization to be verified for specific resources. This allows authentication decisions to be made by comparing resource properties and user claims to support scenarios such as restricting access to the creating user or checking that the user has access to a location associated with the resource.

## Resource Authorization Handler

1. In a new file, add an authorization handler to verify that a user is certified for a craft. As before, the handler uses an `AuthorizationRequirement` to indicate when the requirement is required and pass in any specific properties
```csharp
public class IsCertifiedForCraftAuthorizationHandler :
    AuthorizationHandler<IsCertifiedForCraftRequirement, Craft>
{
    protected override Task HandleRequirementAsync(
	    AuthorizationHandlerContext context,
		IsCertifiedForCraftRequirement requirement,
	    Craft resource)
    {
        if (context.User.HasClaim("craft", resource.Name))
        {
            context.Succeed(requirement);
        }

        return Task.CompletedTask;
    }
}

public class IsCertifiedForCraftRequirement : IAuthorizationRequirement { }
```
1. Before using the handler. it first needs to be registered in the services on startup
```csharp
builder.Services.AddSingleton<IAuthorizationHandler, IsCertifiedForCraftAuthorizationHandler>();
```
1. As the resource needs to be loaded before the handler is called, the authorization needs to be explicitly called. An authorize attribute can be added to the method to verify user level authorisation, but resource level authorisation needs to be done after the resource has been loaded.
	```csharp
	/// <summary>
	/// Controller for Task 09 - Resource based authorization
	/// </summary>
	/// <param name="authorizationService"></param>
	/// <param name="allCraft"></param>
	[Route("Task09")]
	[ApiController]
	public class Task09Controller(
	    IAuthorizationService authorizationService,
	    ILogger<Task09Controller> logger,
	    Craft[] allCraft
	) : Controller
	{
	    [Authorize]
	    [HttpGet("Craft")]
	    public IActionResult GetCraftList()
	    {
	        logger.LogInformation("Returning list of available craft");
	        return Json(allCraft);
	    }
	
	    [AllowAnonymous]
	    [HttpGet("Craft/{craftName}")]
	    public async Task<IActionResult> GetCraft(string craftName)
	    {
	        logger.LogInformation("User querying information for {craft}", craftName);
	
	        var selectedCraft = allCraft.FirstOrDefault(c => c.Name == craftName);
	        if (selectedCraft == null)
	        {
	            logger.LogWarning("{craft} could not be found", craftName);
	            return NotFound();
	        }
	
	        var authorizationResult = await authorizationService
	            .AuthorizeAsync(User, selectedCraft, new IsCertifiedForCraftRequirement());
	
	        if (!authorizationResult.Succeeded)
	        {
	            logger.LogWarning("User is not authorised to access {craft}", craftName);
	            return Forbid();
	        }
	
	        logger.LogInformation("Returning information for {craft}", craftName);
	        return Json(selectedCraft);
	    }
	}
	```
1. Run web app and test with Task 09 view

## Resource Authorization Handlers Logic

`AuthorizationHandler<TRequirement, TResource>` is build on top of the basic `AuthorizationHandler<TRequirement>` , but exposes `context.Resource` as a typed parameter. When performing controller/action authorization, the context Resource is populated with the `HttpContext`, so `AuthorizationHandler<TRequirement, HttpContext>` is roughly equivalent to `AuthorizationHandler<TRequirement>`

```csharp
// These are equivilent
 public class IsCertifiedForCraftRequestAuthorizationHandler :
     AuthorizationHandler<IsCertifiedForCraftRequirement>
 {
     protected override Task HandleRequirementAsync(
	     AuthorizationHandlerContext context,
         IsCertifiedForCraftRequirement requirement)
     {
         if (context.Resource is HttpContext)
         {
             context.Succeed(requirement);
         }
         return Task.CompletedTask;
     }
 }

 public class IsCertifiedForCraftRequestAuthorizationHandler :
     AuthorizationHandler<IsCertifiedForCraftRequirement, HttpContext>
 {
     protected override Task HandleRequirementAsync(
	     AuthorizationHandlerContext context,
         IsCertifiedForCraftRequirement requirement,
		 HttpContext resource)
     {
         context.Succeed(requirement);
         return Task.CompletedTask;
     }
 }

```

If a requirement is intended for use on an `AuthorizeAttribute` as well as an `authorizationService.AuthorizeAsync` call, it requires an implementations for both `HttpContext` and the intended resource type so that both the action and resource can be authorized. This can be implemented as either a single `AuthorizationHandler<TRequirement>`, or as an `AuthorizationHandler<TRequirement, TResource>` for each. Authorization will only succeed if `context.Succeed(requirement)` is called, so a requirement without a handler cannot succeed.
